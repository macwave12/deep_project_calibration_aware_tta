## Setting and protocol
- K1. Zero-shot setting: class names given as text, unlabeled test stream, batch size 1,
  single centre-crop view, prompt `"a photo of a {class}."`, ViT-B/16, seed 0, CoOp splits.
  Same as the benchmark (Sheng et al., Sec. 3). Source: `docs/baseline_hyperparameter_audit.md` §3.
- K2. Our CLIP and TDA accuracies reproduce the benchmark's ViT-B/16 Table 14 within 0.16
  points on all five datasets. Source: audit §4.
- K3. The benchmark reports ECE only for ResNet-50 (Tables 7, 19). Its 5.70 → 9.21 figure
  is the fine-grained average for RN50; full average 6.07 → 11.53. Our ECE (ViT-B/16) has no
  published counterpart. Source: audit §4, arXiv:2506.24000 Table 7.
- K4. TDA's per-dataset α/β come from the official repo, not the paper; the paper's single
  searched setting is α = 2, β = 5 (supp. Table 6), shot capacities 3/2, p_l = 0.03,
  band [0.2, 0.5]. Provenance of per-dataset values unstated. Source: audit §2.
- K5. `cal_tda` inherits TDA's per-dataset β in every variant and α in the additive and
  temperature variants (`CalTDA.prepare_model_and_optimization`). Gate/fusion do not read α.
  Source: `online_method/cal_tda.py` L272–282, L441.

## How TDA works (code-verified)
- K6. Every image is offered to the positive cache under CLIP's pseudo-label; the 3
  lowest-entropy items per class are kept (`tda.py` `update_cache`). No entropy gate.
- K7. Pseudo-labels and entropy come from raw CLIP logits; the fused output is never written
  back. There is no feedback loop. Source: `cal_tda.py` L395–424.
- K8. Write happens before read for both caches: an admitted image votes for its own class
  with weight exp(0) = 1 (+α on CLIP's argmax), and a band image penalizes its own plausible
  classes by 0.117. Source: `cal_tda.py` L414–443.
- K9. TDA's additive rule is a normalized product of experts:
  softmax(z + αc) ∝ p_clip · p_cache^α. Agreement therefore sharpens.
- K10. Negative cache marks classes with p > 0.03 of an uncertain stored image and subtracts
  from them (code); the paper's equations have a double negative. Source: TDA Eq. 4–7, `tda.py` L24.

## Results (P1, seed 0)
- K11. Means over 5 datasets: CLIP 53.16 / 5.57, TDA 56.63 / 11.24, gate 55.01 / 4.61,
  temp 56.60 / 8.54, gate+temp 55.01 / 6.59 (accuracy / ECE). Source: `results/summary.csv`.
- K12. TDA's ECE ≈ |mean confidence − accuracy| on every dataset (DTD 17.4 vs 17.2,
  EuroSAT 14.4 vs 13.1, Aircraft 15.5 vs 15.5): a near-uniform overconfidence shift. Pets is
  the exception (CLIP underconfident, −3.5). Source: `reliability` field of `results/raw/*.json`.
- K13. Margin admission raised confidence and lowered accuracy, worse as admission rate
  falls (Aircraft 16% admitted, gap +16 → +33). Source: `results/raw/ablation/*_margin.json`.
- K14. Ungated fusion is underconfident on all five datasets (gap −9 to −44).
  Source: `results/raw/ablation/*_fusion.json`.
- K15. Gated fusion's mean confidence tracks CLIP's per dataset; it beats CLIP's ECE on
  3/5 datasets (worse on Flowers, Pets). Source: `ablation_gate/*_gate.json`, summary.csv.
- K16. LOO estimate is wrong in both directions: too high on EuroSAT (88% of samples pinned
  at T = 1), too low on Pets (mean T 1.81). On fusion, the search wants T < 1 and the floor
  blocks it. Source: `results/summary.csv` temperature columns.
- K17. Phase 3 chose the gate among four variants evaluated on the test sets;
  `fusion_gate_sharpen` was never run on EuroSAT; `fusion_sharpen` reached 70.93 on Flowers
  (> TDA 69.91). Source: `results/raw/exploration/`.

## Implementation facts
- K18. LOO temperature re-scans the full score history for 381 temperatures per step:
  O(N²). Source: `cal_tda.py` `_estimate_temperature`, `utils/loo_temperature.py`.
- K19. `compute_cache_logits` hard-codes `.cuda()`. Source: `tda.py` L24, L26.
- K20. All single-view methods (clipzs, tda, cal_tda, dmn_weak, ecalp, onzeta) obtain
  features only through `model.forward_features(images)`, so a feature-cache stub can replay
  them. Source: `online_tta.py` L205, method files.
- K21. SUPERSEDED by K31 (2026-11-08). The deck is generated by `presentation/build_pptx.py` from the CSVs; slide 10 is
  hidden. Source: `presentation/`.
- K19 update (2026-11-07, T02): `compute_cache_logits`, `OnZeta.rho` and `DMN_WEAK`'s
  memory bank now use the input tensor's device; bit-identical to the old code on CPU.
  Source: `tests/test_device_agnostic.py`.
- K22. The model is fp32 (`convert_weights` is commented out in `clip/model.py`
  `build_model`); fp16 only comes from CUDA autocast. Under autocast, `forward_features`
  most likely returns **fp32** image/text features (`x / x.norm()` with `norm` on the fp32
  list), not fp16: with fp16 features TDA's `compute_cache_logits` (called outside
  autocast) raises `Half != float`, and the recorded runs did not crash. TDA's `logits`
  are fp16 (matmul under autocast) and its output accumulates in fp16. Inferred from code
  and `tests/test_device_agnostic.py`; T01's `meta.json` records the actual dtype.
- K23. The stream order is drawn when `online_tta.py`'s loop starts iterating, i.e. after
  `set_random_seed(seed)`, `build_dataset` and `get_coop` (CLIP's `__init__` draws random
  initial weights before the checkpoint is loaded). The iterator draws `_base_seed`, then
  `RandomSampler` draws its own generator seed, then `randperm`. Method constructors and
  `prepare_model_and_optimization` of clipzs/tda/cal_tda draw nothing, so all single-view
  methods saw the same stream for a given seed. Source: `online_tta.py` L177–349, torch
  `dataloader.py`/`sampler.py`; `tests/test_feature_extraction.py`.
- K24. `clip.load` only accepts a TorchScript archive (or a known model name); a plain
  state-dict file hits an unbound `model` at `clip/clip.py` L137. Source: CPU smoke test of
  `scripts/extract_features.py` (T01 handoff).
- K25. `data/fewshot_datasets.py` reads `DATA_ROOT` at import time for the split-JSON
  paths, independently of `--data`. Source: `data/fewshot_datasets.py` L123–136.
- K26. CPU `torch.autocast('cpu', float16)` keeps `softmax` in fp16 (CUDA: fp32), so it
  is not a stand-in for CUDA autocast; `utils/feature_replay.cuda_autocast_emulation`
  applies CUDA's cast lists instead. Source: measured on torch 2.15 CPU (T02 handoff).
- K27. Every `online_tta.py` run leaves `<output_dir>/bs1/<arch>/<test_sets>/save_results.pt`
  (run_one: `online_results/ckps/<run name>/bs1/ViT-B/16/<TestSet>/`) with per-step `output`
  and `target` concatenated in stream order; it is overwritten by the next run with the same
  run name. `utils/recorded_run_check.py` uses it to confirm the extracted stream order
  exactly. Source: `online_tta.py` L389–402, `concat_dict`.

## Added by T10 (draft deck v2, 2026-11-08)
- K28. TDA's "normalized" entropy divides an entropy in nats (`torch.log`) by log2 C, so its
  maximum is ln 2 ≈ 0.69, not 1; the negative-cache band [0.2, 0.5] applies to that quantity.
  Source: `online_method/tda.py` L48 and L95.
- K29. ECE ≥ |mean confidence − accuracy| for any binning (triangle inequality), with equality
  iff every non-empty bin errs in the same direction. This is what makes K12 read as a uniform
  shift. Source: definition; checked on every record in `tests/test_deck_evidence.py`.
- K30. Under the 50/50 mixture, class 2 overtakes class 1 iff p1 − p2 < q2 − q1, and
  q2 − q1 ≤ (e^K − 1)/(e^K + C − 1) with K = 3 (cache logits lie in [0, K]). The bound is 0.16 on
  Flowers102/Aircraft (a CLIP gap ≥ 0.2 can never be overturned there) and 0.66 on EuroSAT.
  Under TDA's additive rule the cache can overturn CLIP log-odds up to α·K. Source:
  `analysis/deck_evidence.py`, `results/analysis/dataset_constants.csv`, brute-force test.
- K31. Deck v2 (`presentation/build_pptx.py`): 36 main + 6 backup slides; every numeral is
  formatted through `Results.num`/`Results.illus` and `tests/test_build_pptx.py` fails on any
  other number on a slide or in the notes. Derived statistics come from
  `results/analysis/*.csv` (written by `analysis/deck_evidence.py`); published numbers from
  `results/analysis/literature_values.csv`.
- K32. Gated fusion's mean confidence is within 3.6 points of CLIP's on every dataset
  (`results/analysis/reliability_stats.csv`), i.e. the gate returns to CLIP's calibration.
